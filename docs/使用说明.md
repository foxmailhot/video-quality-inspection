# FrameScope 2.0 视频质检工作台

适用：Windows 10/11，64 位。所有视频处理均在本机完成，不上传视频。

## 启动

推荐运行 `FrameScope-2.0.0-Setup-x64.exe` 安装。安装包包含 Python、Qt、FFmpeg、CUDA 分析运行库，不需要单独配置 Python 或 CUDA 工具包。安装结束会实际检查 GPU 计算环境。首次启用 GPU 需要编译计算内核，可能比后续运行慢。软件无需登录。

安装器自动区分首次安装、旧版升级、同版修复；再次安装会沿用原安装位置并保留设置、背景、队列和报告。阻止用旧安装包覆盖已安装的更高版本。之前使用便携版的用户也会沿用同一 Windows 用户下的使用记录。安装前请结束检测并退出旧版。此处的升级检测是运行安装包时检测本机版本，不是联网自动下载升级。

也可直接打开便携目录中的 `FrameScope.exe`。请保留同目录的 `_internal` 文件夹，不能只移动 EXE。

## 操作

1. 点击“添加视频”“添加文件夹”，或者把视频拖入窗口。
2. 点击上方“检测参数”按钮，在弹窗中调整参数，再点击“开始队列”。队列串行处理，避免多个视频抢占显存。检测时可继续添加视频。
3. 底部显示当前视频的扫描进度、处理帧数、速度和实际计算后端，以及队列完成数量。
4. 检测完成后，问题会出现在视频下方的左下方的七条标记轨道中。点击标记定位；双击问题列表可暂停并跳转到起点。空格播放/暂停。
5. 可把选中的问题设为“确认问题”“误报”或“待复核”。误报标记立即从轨道隐藏；确认问题用更亮的色块和白色描边突出显示。列表保留全部复核状态，随时可以改回待复核。
6. 默认导出 HTML 可视报告，双击即可用浏览器查看问题、复核结论、参数及警告，浏览器打印可存为 PDF。CSV 可用 Excel/WPS 打开。HTML 可重新导入恢复标记，也兼容旧 JSON；原视频移动后会提示重新选择。
7. 用播放按钮旁的“−1 帧”“+1 帧”暂停并移动到相邻的实际视频帧；默认快捷键为 ← / →，可长按。支持连续点击及可变帧率，片头/片尾自动停在边界。双击问题列表同样会解码并显示对应帧。空格恢复正常播放。
8. 左侧队列底部的“一键清空列表”清空全部队列项及当前界面结果；正在检测时会先停止再清空。不会删除原视频或已经导出的报告。
9. 右上角“快捷键”可修改上一帧、下一帧、播放/暂停、添加视频的按键；支持组合键、清空停用、恢复默认和冲突提示，保存后下次启动仍然有效。编辑参数或打开对话框时不会触发播放快捷键。
10. 播放按钮右侧的细播放条用于观看和定位，点击直接跳转，拖动后松开定位，悬停/拖动有时间提示；底部同一行显示状态、检测百分比、短进度条和队列完成数，两者独立。短于播放器时长的检测报告不会缩短播放轨道，播放结束后才显示 100%。

## 监视器与滚轮检查

- 播放和逐帧都使用白色监视器背景。白色区域属于播放器，视频里的真实黑边不做裁剪或替换。默认留少量白色边距便于观察四边。
- 鼠标放在“滚轮逐帧”上：向上下一帧，向下上一帧；标准滚轮一格对应一帧。高精度滚轮会累积不足一格的输入。上一帧/下一帧按钮也支持按住连续移动。
- 逐帧依据实际时间戳，前后操作串行处理，不会并发修改解码器；鼠标输入优先于预读。首次定位到未缓存的长 GOP 素材仍需解码，不能保证所有素材零延迟。
- “自动适配监视器”根据画面比例和可用窗口空间分配高度；可输入“高度”或拖动监视器下方分隔条手动改变大小。“专注监视器”暂时隐藏轨道和列表，供大画面检查；退出后恢复原空间分配。下方左侧轨道与右侧问题列表并排，中间可拖动调整宽度，上下分隔条可调整监视器和整个问题区高度。
- “画面”调整相对于适合窗口的缩放比例，范围 10%–400%；拖动画面可平移，双击居中。“适合窗口 / 居中”恢复 100% 和自动适配。放大后部分边缘可能在窗口外，检查四边时请恢复适合窗口。
- 在“倍速”按钮上滚动，每格增减 0.1 倍，范围 0.1–10 倍；点击恢复 1 倍。播放器可能在高倍速时跳过显示帧，检测仍逐帧扫描。
- 问题列表可拖动列宽，依据自动换行；选中问题后，列表下方显示完整时间、帧号和检测依据，可复制。监视器设置、缩放、播放速度、自定义快捷键和上下/左右区域大小会保存。

## 1.4 播放与逐帧响应

预览仅读取和解码视频，无需重新编码。播放画面的颜色转换及缩放在后台执行，主界面直接绘制已准备的图像。播放待显示队列最多保留最新一帧，避免高倍速或界面忙碌时积累旧画面；确切逐帧操作和检测仍保留每一帧，不靠平均帧率跳步。

逐帧 CPU 解码启用有上限的多线程；正向连续解码、反向提前准备邻帧，预读期间保留当前可用缓存，替换缓存时整段提交。首次跳到未缓存位置仍需要从关键帧开始解码，具体耗时取决于编码、分辨率、关键帧间距和 CPU。主界面响应改善不代表任何电脑都能实时解码所有 4K/8K 素材。

## 黑边与镜像检测

黑边检测逐帧统计上、下、左、右连续暗行/列，分别标明边宽占画面高度/宽度的百分比；默认至少持续 3 帧、边宽至少 0.5%。可调亮度、暗像素比例、边宽和连续帧数。全黑画面交给黑帧检测。黑边使用未裁边的画面，不受“四边忽略”影响；最细小边缘建议使用原始分辨率分析。暗景或有意遮幅仍可能被标记。

镜像检测比较水平/垂直翻转后的画面与相邻帧、近期参考画面的差异，检测单帧及片段候选，并尽量识别切回点。默认回看 30 秒，参考库每 0.25 秒保留一张缩略图；相邻帧逐帧比较。可调匹配差、相比原方向的改善比例、最少帧数和回看时间。没有切回时，片段终点按下一次明显切镜或片尾估计，报告会注明。

镜像是候选检测：相机快速运动、特效、对称构图、镜面反射或强变化可能造成误报或漏检；完全独立且没有正常方向参照的镜头，无法单凭图像确定是否被镜像。请结合白底监视器逐帧复核。

## 自定义背景

点击右上角“界面背景”，操作方式参考 Sonora：上方实时预览，下面调节背景可见度（0–100%）和毛玻璃开关。

- 可选深灰网格、灰白几何、纯色，或导入自己的 PNG / JPG / BMP / WebP 图片。
- 支持“拉伸覆盖整个界面”和“等比铺满（居中裁切）”。
- 点击“应用背景”才会保存到主界面；“取消”放弃本次修改。
- 自定义图片会复制并规范化为 PNG，保存在软件数据目录中；不再依赖原文件位置。超大图片会缩小到最长边 4096 像素以控制内存。
- 背景、可见度和毛玻璃设置随下次启动恢复。效果只作用于工作区，视频播放及逐帧画面不加背景滤镜。

关闭时自动保存队列和参数。中断的检测不会被当作完整报告；重新检测从视频开头开始。结果保存在 Windows 当前用户本地应用数据目录的 `FrameScope/FrameScope` 下。导出可自行选择保存位置。不会修改原视频。

## 参数说明

| 参数 | 含义 |
|---|---|
| 分析尺寸 | 每帧分析宽度，保持宽高比；没有时间抽帧。原始分辨率更适合小范围损坏，显存和耗时更高 |
| 四边忽略 % | 每条边裁去指定比例，仅影响检测，不改变视频；可忽略台标边缘，但该区域的其他问题可能漏检；四边黑边检测始终使用未裁边画面 |
| 暗像素亮度 | RGB 转亮度后 0–255 数值，越大越容易把暗画面判为黑帧 |
| 暗像素比例 | 一帧中暗像素达到多少百分比才算黑帧 |
| 最少连续帧 | 默认为 1，可以检测单帧黑屏；设为 2 会忽略只有一帧的黑屏 |
| 最短持续秒数 | 低变化持续多久才标记为疑似定帧 |
| 容许画面差 | 相对当前静止段起始画面的平均亮度差；越大越敏感 |
| 突变差值 | 夹帧入口的相邻帧平均亮度差；越小越敏感 |
| 返回相似差 | 在限定帧数内回到原镜头的允许亮度差；越大越容易触发 |
| 最多夹入帧数 | 检测 A→B→A 式 1–30 帧短暂插入；不能覆盖所有夹帧类型 |
| 块边界敏感阈值 | 周期边界相对普通边缘的强度；降低可增加马赛克候选 |
| 噪声强度阈值 | 画面高频差异需同时明显高于近期基线，才标记噪声候选 |
| 异常绿紫比例 | 大面积绿色/紫色异常的候选阈值；绿幕、特效可能误报 |

“帧号”从 0 开始，检测时间标记优先使用源视频实际显示时间戳。普通播放和点击时间线由播放器按时间定位；“−1 帧 / +1 帧”和双击问题列表则使用独立解码器按实际帧时间戳显示静帧，不使用平均帧率换算。异常文件缺少可用时间戳时会提示无法精确逐帧定位。1.2 复用解码器，后台预读相邻帧，并直接显示已缓存的画面，避免每点击一次就重新打开视频。缓存预算约 128 MB、最多 48 帧；长 GOP 视频首次定位仍需要解码等待。逐帧预览最长边 1920 像素，仅缩放预览，不改变原视频或检测分辨率。

## GPU 工作方式

默认自动选择可用 NVIDIA 显卡中显存最大的设备。像素亮度、帧差、噪声和块边界统计在 CUDA 上计算；对支持的编码尝试 NVDEC 硬件解码。状态栏和 JSON 的 `info` 字段记录实际后端。

电脑仍需已安装兼容的 NVIDIA 显卡驱动，安装包不替换系统驱动。安装目录的 `runtime-check.json` 记录内置环境与实际 CUDA 运算检查结果。逐帧预览缓存与检测计算各自独立，预览解码不代表所有操作均使用 GPU。

如果该编码不支持硬件解码，会保留 CUDA 分析、回退 CPU 解码并给出提示；CUDA 不可用则回退 CPU 分析。未勾选自动 GPU 时使用 CPU。此版本未实现 AMD/Intel GPU 分析。小视频的 GPU 传输开销可能超过计算收益，不保证所有输入都比 CPU 快。

## 检测边界

- 黑帧检测是明确的像素规则，但黑场转场是否属于错误仍取决于作品。
- 定帧只能识别画面缺少变化，不能区分有意静止、PPT、片尾卡和真正播放卡死。
- 夹帧与花屏使用可解释的启发式规则，属于筛查候选，不是经过行业数据集认证的分类模型。正常切换不满足短暂返回规则，但闪光、闪白转场可能触发。
- 花屏覆盖部分周期块状异常、突发噪声、横向断层及大面积绿紫色异常，无法保证识别局部纹理错误、缺失图层、字幕渲染错误或所有 GPU 渲染故障；也不能确定损坏原因。
- 解码器报告损坏帧时会标记；解码异常终止时显示失败，不能视作检测通过。容器自身也可能隐藏或纠正错误。
- 高位深/HDR 素材转换到 8 位 RGB 分析，不是专业 HDR 色彩合规检测。需要调整阈值，并在专业播放器复核。
- 默认分析第一个视频轨道，不做音频检测。超长素材、特殊编码和真实项目误报率仍需用实际样本验收。

## 源码与重建

`source` 目录包含可修改的 Python 源码、依赖和构建配置。无需编程即可运行提供的 EXE。源码由本次任务新建；使用 PyAV/FFmpeg、NumPy/CuPy 和 Qt/PySide6，未复制其他质检项目的业务代码。

GitHub 调研依据详见 `开源算法调研.md`。本次合成样本验证结果详见 `验证结果.md`。


## 编辑、排序和带截图日志

选择问题后点“编辑”修改。双击表头排序，重复双击切换方向；“默认排序”恢复误报置底。导出日志选 HTML 会自动嵌入起始帧缩略图，可离线打开。提取过程中可取消；CSV 是不带图片的表格。


## 自动更新（2.0）

软件启动后在后台读取GitHub 仓库 foxmailhot 的最新正式 Releases，不上传视频和日志。只有正式版本号比当前版本大时才询问是否下载。下载支持取消，并验证每个分片和整个安装包的大小及 SHA256。下载完成后选择关闭升级，会保存设置、停止工作并打开覆盖安装程序；选择稍后，可点击“设置 → 检查更新”再次安装。网络不可用不影响本地检查。仓库必须允许未登录读取版本记录和附件，否则自动更新无法连接；程序不内置账号令牌。

## 2.1.2 循环回看和帮助

问题详情旁点击“循环回看”，以当前播放头为中心固定前后各1秒循环，靠近片头或片尾会限制范围。空格或再次点击按钮可停止并暂停；定位、逐帧、切换视频和清空会结束循环。即使修改播放快捷键，循环期间空格仍可停止。右上角“帮助”位于设置左侧，集中提供操作指南和当前视频提示。原来队列下方及问题区底部的说明已移入帮助。2.1.1的定位、复核和布局改进一并包含。
